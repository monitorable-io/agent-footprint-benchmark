## Deviations and incidents

- 2026-11-07 22:30Z, **slot 1: the +1 h check did not run.** The runner's host had no network at that tick: ssh to all nine boxes and to the sink failed ("Network is unreachable") and the run-log pull and push failed in the same second, which is why the slot-1 line reads "0/9 rows active; ATTENTION". The boxes were not affected: each of the nine slot-1 files has a sample every 10 s through that hour, and the two hub-registered rows kept reporting (Beszel run 1 sent 2.38 MB per 24 h against 2.32 and 2.41 in runs 2–3; Pulse 16.2 against 16.0 and 16.2). The check right after the start (21:50Z) had passed. The runner retries a failed push only with its next commit, so STATUS showed "run-log push failing" until the collect at 22:56Z on 11-08. No footnote.
- **Monitorable run 1 (box-1) and Beszel run 3 (box-6): disk writes that are probably not the agents' own. Unexplained; published as measured, footnoted on both runs.** Monitorable run 1 was charged 15.8 MB between +0.3 h and +7.8 h after its install (2026-11-08 23:18Z → 11-09 06:49Z) and nothing in the 17 hours after; Beszel run 3 16.6 MB between +0.0 h and +7.0 h (2026-11-10 00:43Z → 07:44Z) and nothing after. Scaled idle-window figures: 14.5 and 15.1 MB per 24 h. What the samples show: (1) the two episodes are alike to a degree two unrelated programs would not be: 607 and 640 sampler ticks with writes, 97 % of them 30 or 40 s apart, about 2.4 MB per hour, and the same ranking of write sizes (20,480 B in 30 % of ticks, then 32,768, 36,864, 24,576–28,672, 16,384); (2) neither agent's other two runs has them: after their first minute Beszel wrote 0 bytes in runs 1 and 2 and Monitorable 0 bytes in run 2; (3) nothing else about either agent changes at the cut-off: CPU, memory, threads and network per hour are flat across it; (4) the Monitorable agent logged nothing in the idle window (`journal_bytes` 0, so no failed or retried export, the one thing that makes v1.7.0 write) and its on-disk footprint at the end equals run 2's to the byte (57,251,083), so its queue file never grew; Beszel's footprint is likewise identical in all three runs; (5) the pilot has no such episode in any run of the rows that write little or nothing (Beszel, Glances, node_exporter, Telegraf, Fivenines). The likeliest reading is that writeback of pages dirtied by another unit on the box was charged to the agent's cgroup for those hours (cgroup v2 charges an inode's writeback to one owning cgroup), but that is a reading, not a finding: both boxes were rebuilt by the next slot, so nothing could be inspected. The 30–40 s spacing proves nothing by itself: it is the kernel's flush cadence and the collector's and Pulse's own writes show it too. Effect on the table: Beszel's median stays 0.0; Monitorable's is 0.3 and would be 0.0 with a clean run 1, so the published figure can only overstate our own row. **Founder's call:** publish with the two footnotes, or redo both runs (two boxes, one 26 h slot, on the founder's words; with the cause unknown a redo may show it again). A harness cross-check for a later run: record each process's own `/proc/<pid>/io` `write_bytes` next to the cgroup's `io.stat`.
