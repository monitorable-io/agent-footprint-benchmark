## Deviations and incidents

(one line each, with the row it affects; these become footnotes)

- 2026-10-31 13:57–14:10Z, **node-exporter run 1 (box-4)**: the sink's Prometheus died at 13:57:20Z (exit 129) — `sink_retarget` sends a SIGHUP right after `docker compose up -d`, and the HUP landed ~180 ms after the container started, before Prometheus had its signal handler; a `docker kill` is never auto-restarted. Found by `cycle status` (empty target list) at 14:08Z, started again 14:10Z, target `up` from 14:11:05Z. No scrapes for 13 min, all inside the excluded first hour (idle window from 14:57Z). `sink/up.sh` now waits for `/-/ready` before the HUP and restarts a dead container (deployed to the sink and proven live 14:2xZ). No footnote on the idle figures; first-hour network for this row is lower than steady state.
- 2026-10-31 13:47–14:18Z, **beszel run 1 (box-0)**: the agent could not register: "fingerprint mismatch" every 5 s against the hub's dry-run record (`box-1`, created 12:27Z), then `401` once that record was deleted — Beszel's universal token is **ephemeral (1-hour TTL)** unless enabled with `permanent=1`; the setup-day enablement had expired and only the dry-run record still carried the token. Fixed 14:18Z by `GET /api/beszel/universal-token?token=…&enable=1&permanent=1` (user auth); box-0 self-registered at 14:18:28Z and is `up`. 31 min of a 5-second reconnect loop fall inside the excluded first hour (idle window from 14:47Z). Footnote candidate for the first-hour figures of this run only.
- 2026-10-31 14:02–14:19Z, **pulse run 1 (box-6)**: the host module registered, but the Docker module was refused every 30 s with `400 invalid_report`: Pulse binds a token to one Docker host and the scoped token was still bound to the dry-run agent `box-3` (offline since 12:59Z). Fixed 14:19Z by deleting that agent through the API (`DELETE /api/agents/docker/runtimes/<id>?force=true`, `DELETE /api/agents/agent/<id>`, admin session + `X-CSRF-Token`). 17 min of refused Docker reports fall inside the excluded first hour (idle window from 15:02Z). **Recurs every slot** unless the previous pulse box is forgotten before the next install: `sink_retarget` now forgets every Pulse agent and every Beszel system at slot start (fix branch `fix/sink-prometheus-reload-race`).
- 2026-10-31 (Opus review of harness PR #3): in Pulse 6.6.0 removing the last host agent that uses an API token **revokes that token** (`internal/monitoring/monitor_agents.go`), so forgetting the previous slot's Pulse box with one shared `PULSE_TOKEN` would have broken the next Pulse install with 401. Design changed in PR #3: `cycle start` mints a scoped agent token per slot (`POST /api/security/tokens`, name `bench slot-<s> <box>`) and the previous slot's agent is removed afterwards, which revokes only that slot's token. The setup-day `PULSE_TOKEN` in bench.env is now only the dry-run token. Not a measurement deviation: slot 1 ran on the setup-day token, which stays valid while box-6 holds it.
- Lesson for the run log: the three incidents share one cause — hub state left by the setup-day dry runs (a down Beszel system, a bound Pulse token) and a hub whose auto-registration had silently expired. `cycle status` at +1 h would have caught them; the immediate status pass right after `cycle start` caught them within the warm-up hour instead. Keep that immediate pass.
